# Selected internal import policies v1

This bounded extension selects `DEFAULT`, `RECORD_DUPLICATES` or
`REJECT_CIRCULAR` through a package-private enum. The existing three-argument
evaluate call delegates to Default. Null selectors refuse before filesystem
access. There is no numeric flag adapter or exported .NET facade.

The original BI01-BI09 bytes and original v3/v4 captures remain unchanged.
Eighteen new same-profile native location observations extend the two individual
flagged profiles. The versioned bridge compares every predecessor field after
exact copied fixture-root prefix replacement; only newly observed diagnostic
and exception end coordinates extend the envelope. Raw messages, null codes,
ordered events, import/getter availability, failure fields, collection cleanup
and marker absence remain evidence. Java does not claim native cleanup counts,
localized message text, exception ABI or HResult parity.

Unique import edges contain owner, target and first-import start coordinates;
the root is absent. The recording list is explicitly unavailable outside record
mode, and contains first imports plus ordinary duplicates in encounter order.
False imports, root self-imports and circular edges are absent. Property contents
evaluate once. Completed diamond imports are duplicates rather than ancestors.

Root reimports warn MSB4210 and succeed before either flag is considered.
Ordinary duplicates warn MSB4011 with observed first-import context. Non-root
circular record imports warn with an actual null code and owner/target/current
context. Reject preserves that null-code warning, then null-code error, then a
typed private CIRCULAR_IMPORT failure. Missing imports retain MSB4019 and a
MISSING_IMPORT reason. Failures expose immutable diagnostic snapshots and no
successful Result. Circular context contains no invented previous site or full
ancestor chain. Per-call state and immutable result/edge/diagnostic lists prevent
success/failure calls from sharing evaluation state.

The packaged runner retains all 65 existing comparisons and adds 18 selected
profile comparisons. The focused command is `verify.py --focus-profiles --out`
with a new D: project output directory. Resource floors, 128 MiB heaps, two CPU
limits, execution deadlines and restricted JDK-only module launch remain intact.
No Build, restore, target, task, network or download operation is introduced.

F01-02 full chains, full localized messages, public Project/ElementLocation/
ProjectLoadSettings/exception/logger ABI, combined flags, other graphs/platforms,
Unicode/items/globs/SDK/environment/hostile filesystem, shared core/lifecycle,
release/rights/dependencies, E01-E03/N01/NF and product eligibility remain open.
No accepted task, numbered batch or release qualification is claimed.
