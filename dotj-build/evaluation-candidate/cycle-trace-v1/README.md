# Bounded private import-cycle traces

This adaptation retains the existing evaluation result, diagnostic and failure ABI.
The new sidecar records the actual root-to-owner ancestry and the closing import,
with a cycle start index and links to the existing diagnostic indices. Native
MSBuild has no corresponding public Chain field. Trace expectations are authored
from the pinned source algorithm and exact fixture import sites before product edits.

The contract freezes 19 graphs, three individual profiles and 14 private control
groups. Native projection coverage requires two independent passes on Windows and
the measured Linux Docker case-enabled 9p/NTFS profile. The 190 missing row-passes
supplement retained full-field observations; missing end coordinates are never
inferred. The completed Record child of the historical FAILED capture is reused
as a child unit, and that aggregate remains FAILED.

The original 16-file and 65,536-byte limits imply at most 17 path entries and 16
edges in a witness. There is no new trace-count limit. In-sandbox import aliases
retain their existing admission rules. CC09 marker variants are separate from
the byte-exact reused BI fixtures. CC05/CC11 include bounded two-thread isolation.

This is internal JDK-only evaluation, not a public Microsoft.Build facade. E01
rights/notice release review, E02 recursive dependencies, E03 full behavior,
N01 representation/public ABI and SDK acceptance remain open. Source and installed
MSBuild pins have separate evidence roles; source-build equivalence is unproven.
No upstream code is copied into the Java implementation. The native observation
probe is this repository's retained development-only probe. F01-02 remains a
partial adaptation and no task or framework acceptance credit is implied.

The executed successor uses `contract-v2.json`. The original `contract.json`
remains historical: its trace columns were one too high. The root independently
audited all 190 edge occurrences against the literal `<Import` token, native
ancestry edges and closure diagnostics on both operating systems. The additive
amendment changes only those columns; fixture bytes, topology, diagnostic links
and the native lock remain unchanged.
