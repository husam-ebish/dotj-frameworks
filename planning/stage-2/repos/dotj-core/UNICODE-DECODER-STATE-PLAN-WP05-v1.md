# UnicodeEncoding specialized decoder array reference and plan

Batch 2241 captures the native UnicodeEncoding decoder state contract before implementing an owned Java decoder. The current Java UnicodeEncoding still inherits the generic default decoder; this reference packet does not qualify it. The source count remains 98, with no product Java change in this batch.

The pinned .NET 10.0.12 capture has ten byte-order/fallback configurations, 130 byte inputs and 11,640 partition sequences. Each partition sequence alternates count/write across two blocks and a final empty flush, recording 69,840 calls. Another 24,480 capacity cases each record a seed write, non-consuming count, bounded-capacity write and empty flush: 97,920 calls. The six seed states include empty input, an odd byte, a high-surrogate word and high-surrogate plus partial-word state. The 360 reset/fallback-change cases add 1,080 calls. Finally, 960 modern array controls capture null priority, negative/range/overflow validation, ignored count-call destination arguments and successful empty boundaries. Total recorded calls: 169,800. Factory observations verify fresh decoders, initial sharing, detachment after owner changes, current owner fallback for new decoders and owner independence after decoder changes.

Strict failures include indexes -2 and -1 that refer to earlier-call bytes. These must be preserved by the implementation rather than constrained to the current input slice.
