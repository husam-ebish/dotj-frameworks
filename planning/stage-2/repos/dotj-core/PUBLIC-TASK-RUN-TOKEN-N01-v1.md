# Selected Task.Run(Action, CancellationToken)

This contract adds exactly `public static Task Run(Action action, CancellationToken cancellationToken)`. Current qualification and integration status belongs to [Batch-2519](../../implementation/batches/Batch-2519.md). The [selected workload evidence](evidence/public-task-run-token-v1.json) retains actual baseline, native, product, private and historical captures. Foundation completion is recorded separately in `public-task-run-token-foundation-v1.json` after its actual gate completes.

Run validates the action first. Java null cancellation tokens are rejected second with `ArgumentNullException("cancellationToken")`; CLR tokens are value types, so this is a representation policy. Every valid call queues work, including a requested token. The worker checks the associated token once at entry. A requested token suppresses the action and produces cancellation with the original Task and associated token in `TaskCanceledException`. A held executor stays pending when the source is canceled until that work actually enters. No synchronous status at the return from Run is promised.

Once the entry check passes, cancellation alone neither interrupts the action nor forces a canceled result. A request in the check-to-invocation window may still allow invocation. A normal return succeeds; an ordinary exception faults even if cancellation was requested. At action exception handling, only an `OperationCanceledException` whose token equals the associated requested token produces cancellation. Equality follows token source/value identity, including different equal Java token objects. The original matching OCE is retained and rethrown by repeated awaits; the canceled Exception property is null. Unrequested, default/None, foreign and Java-null OCE tokens fault with the original exception and a single outer AggregateException. The existing one-argument Run retains its all-OCE-fault profile.

Runtime-queued Run acquires no cancellation registration, timer or cancellation-disposal obligation. Disposed tokens retain their requested state. Completion publication and continuation dispatch stay outside the action catch. Private held executors and an immutable per-invocation after-entry barrier establish Java interleavings; they are source-supported controls, not native thread-pool scheduling observations. Public Task construction and producer authority remain unavailable.

The shared daemon helper now uses the JDK constructor that prevents creator InheritableThreadLocal inheritance when a fresh thread is constructed. This corrects a source-derived predecessor behavior and applies to work, continuations, failure reporting and rejection fallback. It does not clear arbitrary task-written ThreadLocals on reused cached workers or emulate CLR ExecutionContext capture. A first-use JVM and actual fallback/continuation controls exercise this boundary. Executor rejection remains observable on a daemon, with the work invoked in finally even when the reporting handler throws. Foreign Java Throwables keep the original cause in a System.Exception wrapper. Catastrophic inability to create a thread remains outside the delivery guarantee.

The two native matrices contain 25 designed cases and 300 typed fields, each observed in two passes with explicit Action typing on pinned .NET 10.0.12. Only selected Action assertions from `TaskRtTests.RunRunTests` and `RunRunTests_Cancellation_Negative` support the mapping; the upstream xUnit suite, generic/unwrap/AttachedToParent behavior and public Wait are not claimed. Repeated identity fields for synthesized skipped-action TCEs express only an applicable original-exception identity assertion; synthesized object reuse is not a contract. New consumers compile against only the explicit candidate JAR and check CodeSource. Historical Task, Task-backed ValueTask, WorkTask/CancelAsync, delegate, cancellation, ValueTask and Delay behaviors are replayed on that same JAR.
