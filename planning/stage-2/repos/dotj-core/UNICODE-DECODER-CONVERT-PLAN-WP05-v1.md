# UnicodeEncoding Decoder.Convert native reference and plan

Batch 2244 establishes the specialized decoder Convert array contract before implementing it in Java. The candidate still inherits the generic halving Convert adapter. This reference packet does not qualify that adapter or credit an implementation task.

The pinned .NET 10.0.12 capture contains ten byte-order/fallback profiles, six decoder seed states, seventeen byte inputs, both flush modes, eight destination capacities and two offsets. Each of the 32,640 sequences records its seed write, initial Convert, continuation using the exact signed bytesUsed, and final empty flush. Another 520 null/range/overflow controls bring the total to 131,080 recorded calls. Whole destination buffers, bytesUsed/charsUsed/completed outputs, remaining fallback data, exact exceptions and later state are captured.

Two observed behaviors are requirements of this pinned contract. There are 456 successful initial calls with bytesUsed -1 when pending state and capacity-driven backtracking interact. The continuation therefore uses source index 1+bytesUsed and can include the captured outer prefix byte. These results must not be silently clamped. There are also 588 successful initial calls with visible fallback characters beyond the reported charsUsed. DecoderFallbackBuffer.InternalFallback can write a prefix before reporting insufficient space; its character pointer is committed only on complete fallback success. A verifier must compare the full destination, including slots beyond the reported count, while protecting elements outside the supplied capacity. It must not assume those unreported slots are unchanged.

The executable reviewer binds runtime/CoreLib/producer hashes and the pinned archive/member hashes for UnicodeEncoding.cs, DecoderNLS.cs and DecoderFallback.cs. It checks corpus size, seeds, guard priority, output bounds, protected outer elements, fresh-state empty continuations, signed counters and the unreported-write observations. Five corruption controls reject a changed runtime, clamped signed counter, modified protected buffer, producer bytes and invented task acceptance. This is native reference consistency and source review, not an independent complete semantic proof or Java qualification.

The implementation plan requires the owned decoder's partial-conversion path to preserve exactly the captured bytesUsed/charsUsed/completed outputs, fallback byte/index payloads, destination prefixes and pending odd-byte/high-surrogate state. A packaged consumer must compare every captured outcome and continuation before selected array Convert qualification. Convert heap spans, arbitrary custom fallback-buffer protocols/reentrancy, pointer/byref lifetimes, source ABI, cross-method dispatch and E01/E02/E03/N01/Q01 remain open.

No product Java code or class is added by this batch; the source inventory remains 98. The canonical gate, compiled API audit and retained packaged/source/map/notice/distribution checks remain mandatory. No accepted task or qualified framework is credited. The Java product remains JDK-only, while Python and pinned .NET are development/reference tools. The broader dependency graph and public .j installer/feed remain unresolved. Batch 2500 is the authorized numbered milestone and total project batches remain unknown.
