# Selected stateful UTF-8 Decoder arrays

Batch 2189 adds System.Text.Decoder and UTF8Encoding.GetDecoder for the selected array surface, with and without explicit flush arguments. Each call creates an independent state object and shares the encoding's initial fallback reference. The UTF-8 decoder retains valid incomplete byte prefixes, combines them with later input, emits UTF-16 scalars, flushes through the configured fallback and clears state on Reset. Count calls observe pending input without consuming it. Failed processing of a pending prefix preserves its native recovery state, independently of the encoder's different failure behavior.

The native oracle covers every single byte, selected byte-pair/triple combinations, scalar boundaries and malformed sequences: 422 input vectors, seven configurations and 14,798 split-input scenarios. Forty decoder baseline sequences add Reset, fallback changes and recovery. The packaged consumer passes 133,412 groups over 88,908 calls, comparing counts, destinations, native exception byte payloads and negative/relative indices. Candidate destinations are 24 elements; recorded 64-element baseline tails are verified unused. These are sufficient-capacity tests, not small-buffer qualification.

The new Decoder source and nested implementation are explicitly added to the owned class map and both build profiles. Separate Type compilation, combined consumers, map binding, rights inputs, JDK-only distribution and shared typeof lowering remain required. These selected array transitions do not qualify arbitrary custom stateful buffers, direct external-buffer mutation, small capacities, Convert, spans, pointers, full metadata/source ABI or WP-05-T2 acceptance. No accepted task or qualified framework is credited. Next is native decoder validation, small-destination recovery and direct fallback-property controls.
