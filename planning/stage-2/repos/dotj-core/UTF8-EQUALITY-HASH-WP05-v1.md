# Selected UTF-8 equality and hash behavior

Batch 2182 adds logical Equals(Object) and GetHashCode dispatch on Encoding and UTF8Encoding. The UTF-8 comparison requires another UTF8Encoding, the same preamble configuration, equal encoder fallbacks and equal decoder fallbacks. Read-only state, cloning and a derived runtime class alone do not change equality. The hash adds the two fallback hashes, code page 65001 and one when the UTF-8 preamble is enabled, using signed 32-bit wraparound.

The pinned runtime capture records 82 configurations: direct and derived constructors under four flag combinations, Encoding.UTF8 and its clone, and all 72 combinations of six encoder and decoder fallback choices under both preamble flags. It records 6,724 ordered equality pairs. The packaged consumer passes 7,298 groups, including the pairs, clone/null/foreign-object controls, formula and process-local hash stability. Equal objects must hash equally. Raw random-seeded hashes from different processes are not compared, and a coincidental unequal-object hash collision is not treated as a parity obligation.

The Java facade keeps the exact logical uppercase names; this does not qualify lowercase java.lang.Object.equals/hashCode interoperability. Arbitrary custom fallback overrides, other encoding families, full metadata/source ABI, stateful encoders and WP-05-T2 acceptance remain open. Base Encoding dispatch is exercised through selected UTF-8 instances; arbitrary custom Encoding subclasses are not qualified. No accepted task or framework is credited. Next is observable custom fallback Equals/GetHashCode dispatch, short circuiting and exception propagation.
