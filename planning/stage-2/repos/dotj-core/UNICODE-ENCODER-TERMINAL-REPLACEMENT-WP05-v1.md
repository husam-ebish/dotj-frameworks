# UTF16 stateless terminal replacement edges

Batch 2251 qualifies selected stateless encoder arrays where malformed UTF16 input occurs only at the terminal position. Eighteen endian/replacement configurations and eight source shapes produce 2,880 native cases. Empty and normal input, standalone high/low surrogate, a valid pair, and normal-prefix terminal malformed/pair cases exercise counts, optional count-before-write, output capacities, offsets and empty tails. All selected calls returned under pinned .NET 10.0.12.

The baseline incorrectly treats a NUL in a replacement string as a literal encoded character. For a terminal high surrogate, standalone NUL replacement and zero output capacity, native writes zero bytes while the baseline throws output overflow. The correction uses the actual fallback buffer in the stateless path, as it already does for arbitrary fallback implementations. NUL terminates the current fallback read. The dedicated packaged consumer compares 12,960 groups covering exact outcomes and full destination buffers, including protected prefixes. The source inventory remains 98 and no class is added.

This is a deliberately bounded terminal-input qualification. Exploratory nonterminal input found that merely draining a replacement string does not reproduce native scheduling when residual fallback data follows NUL and more input remains. Such interleavings remain mismatched and unqualified. The combined reference preserves the separate native bounded no-return observations; none are counted as Java passes.
