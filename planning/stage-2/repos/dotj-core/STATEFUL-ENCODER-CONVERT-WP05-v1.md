# Selected UTF-8 Encoder Convert arrays

Batch 2200 implements the selected UTF-8 Encoder.Convert array overload for predefined replacement and exception fallbacks. It reports consumed UTF-16 units, written bytes and completion; retains pending high surrogates and buffered fallback output; resumes partial output; and preserves destination writes and initialized output values when a conversion throws. The bounded candidate consumes Unicode scalars atomically and preserves replacement-buffer cursor state when the destination fills.

The Encoder facade uses separate one-element int[] carriers for charsUsed and bytesUsed, followed by boolean[] completed, as planned in Batch 2199. Null or empty output carriers are Java adapter errors checked before conversion; these are not native managed-reference exception projections. Output writes occur only after successful conversion and follow the pinned EncoderNLS assignment order. Destination snapshots preserve writes through exceptional completion while limiting writes to the selected capacity. Heap allocation, aliasing of the two integer outputs and full source ABI are not qualified by this batch.
