# UnicodeEncoding specialized decoder array Convert

Batch 2245 implements a streaming Convert path inside the owned Unicode decoder. It works from local pending-byte/high-surrogate state, consumes a maximal prefix under the destination capacity and commits state when the native partial-conversion path returns. Strict fallback and no-progress overflow exceptions retain pre-call input carry while exposing any preceding physical writes. Successful completion reports the native consumed/written/completed values, including selected bytesUsed -1 results.

The destination capacity is snapshotted and copied back in a finally block. Fallback output can modify that snapshot before capacity failure; the reported character position advances only when fallback completes. A successful partial return can therefore expose characters beyond charsUsed. Capacity-driven input backtracking preserves the native signed result and pending state. End-of-input fallback retains pending high/odd-byte data when the native path cannot finish it. The continuation consumes exactly the recorded signed byte count rather than clamping it.

It compares exact exception payloads, full destination buffers, consumed/written/completed outputs, remaining fallback data, seeded carry and two later conversions. All 456 signed-counter cases and 588 unreported-prefix cases are included, alongside 520 modern null/range/overflow controls.
