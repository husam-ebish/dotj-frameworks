# WP-01-T1 nullability, type identity and exception contract v1

Profile: pinned .NET 10.0.12 CoreLib and a bounded Java 21 foundation candidate. Status: **provisional; DJ-001-WP-01-T1 remains in progress**. This contract describes selected observations and explicit mapping decisions. It does not qualify the full `System.Type` or `System.Exception` public API.

| Topic | Pinned observation | Java candidate decision | Qualification boundary |
|---|---|---|---|
| Closed generic identity | Repeated `Dictionary<string,int>` and reconstructed `List<int>` have the same CLR type identity; selected different type arguments differ. | Keep generic definition, ordered arguments and loader identity in the internal type key. Current `TypeIdentity` checks concrete Java reflection types by structural equality and rejects wildcard/type-variable forms. | The internal key is not `System.Type`; its full public representation and CLR type-loading behavior are open. |
| Open generic parameters | The pinned `List<>` and `Dictionary<,>` definitions return one and two canonical generic parameter `Type` values with positions 0 and 0/1. | The selected Java `System.Type` candidate now returns definition-specific, stable parameter objects and defensive arrays; the external consumer checks the list case. | Generic parameter names, constraints, declaring methods, variance and the complete reflection surface remain open. |
| Selected type-name lookup | The pinned oracle resolves `System.String`, `System.Int32`, ``System.Collections.Generic.List`1`` and ``System.Collections.Generic.Dictionary`2`` to canonical types, and returns null for `System.Unknown`. | The public `System.Type.GetType(String)` candidate recognizes only these four exact names and returns the canonical selected Type value or null. The external Java consumer no longer needs a test bootstrap factory. | Java `String` remains a backend type; assembly resolution, other overloads, null-error parity and the complete type-name grammar remain open. |
| Null input | Pinned `System.Type.MakeGenericType(null Type[])` and `Type.GetType(null)` throw `System.ArgumentNullException` with `ParamName=typeArguments` and `typeName`, respectively. | The selected Java `System.Type` candidate throws a same-named `System.ArgumentNullException` and exposes the selected parameter name; the external consumer checks it. The separate internal `TypeIdentity.of(null)` still uses `NullPointerException("type")`. | The Java exception hierarchy is a candidate backed by `RuntimeException`; full constructor/message, `System.Exception`, and other null-input parity remain open. |
| Disposal exception | In the selected `using` case, a failure from `IDisposable.Dispose` takes precedence over the body failure; the caught exception is the same instance thrown by `Dispose`, and its `InnerException` retains the same cause object. | The product `System.IDisposable.Dispose()` interface dispatches to its implementation. The Java consumer confirms a thrown implementation `Throwable` is propagated as the same object. | General `System.Exception`/`InnerException` representation, stack behavior, and Java cause conversion are open; the interface imposes no universal failure policy. |
