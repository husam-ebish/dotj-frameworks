# Selected stateless Encoding span conversion

Batch 2195 adds five selected heap span overloads to Encoding: GetByteCount(ReadOnlySpan<Character>), GetBytes(ReadOnlySpan<Character>,Span<Byte>), GetCharCount(ReadOnlySpan<Byte>), GetChars(ReadOnlySpan<Byte>,Span<Character>) and GetString(ReadOnlySpan<Byte>). They use the existing typed copy operations and selected array surface. Writing copies the destination snapshot back on success or failure so partial output is visible only inside the supplied view. Inputs preserve raw UTF-16 code units and bytes.

The pinned runtime capture invokes actual span overloads through emitted delegates. It records 3,222 requests under seven UTF-8 configurations, producing 22,554 scenarios with complete/sub/empty source views, six capacities and three destination offsets. The packaged consumer passes 43,218 groups, including native output/failure payloads and complete backing destinations. Five mismatched-carrier programs fail compilation. GetString results are checked as String values, independently of numeric count/write returns.

This is selected UTF-8 heap-view behavior. Materialization and copy-back do not establish CLR allocation, stack/byref, pinning or concurrency parity. Java null span references and raw erased mismatches are host-domain adaptations. Other encodings, TryGetBytes/TryGetChars out-parameter APIs, Preamble span exposure, pointers, complete metadata/source ABI and WP-05 acceptance remain open.
