# Small-integer NumberStyles parsing

Batch 2155 adds the remaining selected NumberStyles String/Char/UTF-8 Parse and TryParse overloads for SByte, Byte, UInt16 and UInt32. The shared JDK BigInteger parser supports integer whitespace/sign flags, parentheses, decimal/group separators, exponent and currency grammar, and hexadecimal/binary input. Raw radix values use the target width: signed-byte FF is -1, while Byte FF is 255. Unknown bits and incompatible radix/style combinations are rejected.

The parser validates complete syntax before reporting range/fraction overflow. String Parse checks null before invalid style; TryParse checks invalid style before resetting a null input's output. Provider errors propagate without resetting the previous output. UTF-8 views retain their encoding so String/Char-only nonbreaking-space token leniency does not leak into Byte parsing. Default String parsing now shares the Integer-style implementation; its obsolete private grammar helper is removed.

Pinned CoreLib 10.0.12 records 124,236 String rows, 33,696 Char/UTF-8 span rows and 612 provider controls. The matrix includes every decimal flag combination on a focused corpus, seventeen named/selected styles on 440 inputs across three numeric providers, and ten invalid masks. Compiled consumers stream the compact evidence and verify 381,484 groups. Existing String and typed-span regressions pass another 9,672 and 47,136 groups. The signature inventory distinguishes 132 direct projections from forty native overloads represented by twenty typed parsing bridges, plus four formatting bridges.

NumberStyles is a Java reference carrier. Java callers passing a literal null to Parse(String, ...) must cast it to IFormatProvider to distinguish the provider and style overloads; the packaged consumer records that source adaptation. Native generic-interface arity, CLR value/byref ABI, additional culture/provider domains, implementation-task acceptance and release qualification remain open. The product remains JDK-only; all temporary artifacts and validation tooling stay on D:.
