# Selected computational Task and CancelAsync

Status: implemented candidate with targeted same-JAR verification. Independent task review, root full gate, final-artifact qualification, whole-branch review and integration remain pending. No task or framework acceptance credit.

Exactly three public APIs are added: `Task.Run(System.Action)`, `Task.FromException(System.Exception)` and `CancellationTokenSource.CancelAsync()`. ObjectDisposedException overrides the inherited Message getter. No public Task producer mutation or test seam is exposed.

Run queues an action on the private daemon executor. Its states are WaitingToRun (2), Running (3), then success (5) or fault (7); only 5/6/7 are terminal. Original System.Exception instances, including foreign-token OperationCanceledException, remain faults and are thrown unchanged by awaiting. Task.Exception adds one outer AggregateException. Completion and continuation dispatch occur outside the action catch scope. FromException rejects null and returns an already-faulted task with original identity.

CancelAsync checks disposal first and returns a faulted Task with the named source ObjectDisposedException. The first request synchronously marks cancellation and stops the timer. An empty registration list returns CompletedTask; otherwise one real Task.Run worker claims the source-owned list at worker entry and drains it serially in reverse registration order outside the lock. Disposal before claim clears callbacks; disposal after claim cannot revoke the worker list. Registration Unregister/Dispose and self-disposal retain their existing behavior. Callback System.Exception failures all run and aggregate in LIFO order. Repeated requests return CompletedTask immediately, independently of the first operation's work or faults. Source cancellation does not cancel the returned task. Late Register invokes inline outside the lock and returns an empty registration, including after requested-source disposal.

ObjectDisposedException supplies its own null-message default and appends the platform newline and object name only for nonempty names. Base CTS naming is paired; arbitrary CLR-derived type name mapping remains unqualified.
