## Discovery acceptance rule

For each new candidate create ID UD-<target>-<sequence>, source URL and package identity, observed reference file/revision, dependency class, required capability, selected version/license, proposed disposition and blocking scope. Dispositions: JDK equivalent with verified behavior, owned .j module, additional owned source scope, justified external/native/platform dependency, or unresolved blocker. “Not in inventory” is never a removal justification.
